我们将创建 32 位汇编程序, 因为大多数恶意软件都写在 32 位模式下, 以便尽可能攻击最多的系统. 请记住, 虽然我们绝大多数人用的都是 64 位操作系统, 32 位程序仍然可以在上面运行.

在汇编方面, 我们大部分时候都在使用 Intel 语法, 不过接下来我会重点讲原生的 AT&amp;T 语法. 正如我在之前的教程里演示过的, 在 Intel 语法与 AT&amp;T 语法之间来回转换非常容易.

每个汇编语言程序都分成三个段:

1)__数据段 (Data Section)__: 这个段用于声明已初始化的数据或常量, 因为这些数据在运行时永远不会改变. 你可以声明常量值, 缓冲区大小, 文件名等等.

2)__BSS 段 (BSS Section)__: 这个段用于声明未初始化的数据或变量.

3)__代码段 (Text Section)__: 这个段用于存放实际的代码, 它以一个全局的 \_start 开头, 用来告诉内核从哪里开始执行.

注释的使用对任何开发都至关重要. 在 AT&amp;T 语法中, 我们用 \# 符号来声明注释, 因为对应行中该符号之后的任何内容都会被编译器忽略.

请记住, 汇编语言语句是一行一条输入的, 你不需要像许多其他语言那样在行末加分号. 一条语句的结构如下:

__\[标签\] 助记符 \[操作数\] \[注释\]__

一条基本指令有两个部分, 第一部分是所执行指令的名字, 也就是助记符, 第二部分是这条命令的操作数或参数.

我想花点时间讨论一下 AT&amp;T 版本和 Intel 语法版本中第 20 到 22 行的代码. 这组指令利用了我们所说的软件中断. 在 AT&amp;T&nbsp;语法的第 20 行, 我们写 __movl $1, %eax__, 意思是把十进制值 1 移入 eax, 它指定了 sys\_exit 调用, 这会正确地终止程序执行并交还给 Linux, 从而不会出现段错误. 在第 21 行, 我们写 __movl $0, %ebx__, 把 0 移入 ebx 以表明程序成功执行, 最后我们看到 int __$0x80__.

第 20 行和第 21 行为软件中断做好准备, 我们在第 22 行用 int __$0x80__ 指令调用它. 让我们再往深处看一点.

在 Linux 中, 内存有两个截然不同的区域. 在任何程序执行时, 内存的最底部是内核空间 (Kernel Space), 它由调度器 (Dispatcher) 部分和向量表 (Vector Table) 组成.

在任何程序执行时, 内存的最顶部是用户空间 (User Space), 它由栈, 堆以及你的代码组成, 这些都可以用下面的图来说明:

<div class="slate-resizable-image-embed slate-image-embed__resize-middle"><img src="/imgs/1520146256303.jpg"/></div>

当我们像上面演示的那样加载好这些值并调用 INT 0x80 时, 用户空间中 ASM 代码段里紧接的下一条指令地址, 也就是你的代码的地址, 会被放入栈中的返回地址区域. 这一点至关重要, 这样当 INT 0x80 完成它的工作后, 就能正确知道接下来该执行哪条指令, 以确保程序按顺序正确执行.

请记住, 在 Linux 的现代版本中, 我们使用的是保护模式 (Protected Mode), 这意味着你无法访问 Linux 内核空间. 上面图中横穿中间的那条长线以下的所有内容, 都代表 Linux 内核空间.

自然会问, 为什么我们不能访问它? 答案非常简单, Linux 不会允许你的代码访问操作系统内部, 因为那将非常危险, 任何恶意软件都可以操纵操作系统的这些组件, 来追踪用户的按键, 活动之类的东西.

此外, 随着新软件的安装与卸载, 以及系统补丁和升级, 现代 Linux 操作系统架构会不断改变这些关键组件的地址. 这正是保护模式操作系统的基石.

我们的代码与 Linux 内核通信的方式, 是通过一个内核服务调用门 (kernel services call gate), 它是你的程序所在的用户空间与内核空间之间的一道受保护的关口, 由 Linux 的 0x80 软件中断来实现.

在内存最最底部, 也就是段 0, 偏移 0 所在的位置, 有一张包含 256 个条目的查找表. 每个条目都是一个内存地址, 包含段和偏移两部分, 每个条目占 4 字节, 因为前 1,024 字节被保留给这张表, 那里不能放任何其他代码. 每个地址称为一个中断向量 (interrupt vector), 它们整体构成所谓的向量中断表 (interrupt vector table), 其中每个向量都有一个 0 到 255 的编号, 向量 0 首先占用字节 0 到 3. 接着是向量 1, 它包含 4 到 7, 依此类推.

请记住, 这些地址都不属于常驻内存. 固定不变的是向量 0x80, 它指向服务调度器, 而服务调度器又指向 Linux 内核服务例程.

当返回地址从栈中弹出并回到下一条指令时, 这条指令称为中断返回 (Interrupt Return) 或 IRET, 它完成程序流程的执行.
