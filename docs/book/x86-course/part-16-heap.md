## Part 16: 堆

我们在基本恶意软件逆向工程 (Basic Malware Reverse Engineering) 章节的下一步聚焦于堆.&nbsp;请记住, 栈向下增长, 堆向上增长.&nbsp;随着我们在后续教程中不断向前推进, 理解这一概念非常非常重要.

<div class="slate-resizable-image-embed slate-image-embed__resize-full-width"><img src="/imgs/1520241941781.jpg"/></div>

堆是你计算机内存中不会自动为你管理, 也不由 CPU 那么紧密管理的区域. 它是自由流动的内存区域, 并且比栈所分配的内存更大.

要在堆上分配内存, 你必须使用 __malloc()__ 或 __calloc()__, 它们是 C 的内置函数. 一旦在堆上分配了内存, 你就得负责释放它: 当你不再需要那块内存时, 使用 __free()__ 将其释放.

如果你不做这一步, 你的程序就会出现所谓的内存泄漏. 也就是说, 堆上的内存仍会被保留, 无法供其他需要它的进程使用.

与栈不同, 堆对变量大小没有尺寸上的限制. 唯一会限制堆的, 是你计算机的物理限制. 堆内存的读取和写入会稍慢一些, 因为你必须使用指针才能访问堆上的内存. 当我们进入 C 教程系列时, 会对此进行演示.

与栈不同, 在堆上创建的变量可被程序中任意位置的任何函数访问. 堆变量本质上是全局作用域的.

如果你需要为 struct 或大型数组之类的东西分配一大块内存, 并且需要让该变量在程序的相当长一段时间内一直存在, 而且还必须能被全局访问, 那么你就应该为此选择堆. 如果你需要的数组和 struct 这类变量能够动态改变大小, 比如可以按需增长或缩小的数组, 那么你很可能需要在堆上分配它们, 并使用 __malloc()__, __calloc()__, __realloc()__ 和 __free()__ 这类动态内存分配函数来手动管理那块内存.
