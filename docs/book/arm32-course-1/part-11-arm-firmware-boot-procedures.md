## Part 11 - ARM 固件启动过程

关于所有 Lesson 的完整目录, 请点击下方链接, 它会给出每节 Lesson 的简介, 以及将涵盖的主题.&nbsp;https://github.com/mytechnotalent/Reverse-Engineering-Tutorial

让我们花点时间聊聊, 当我们第一次给 Raspberry Pi 设备上电时会发生什么.

Pi 一通电, 最先运行的是图形处理器, 因为主处理器被保持在复位状态, GPU 则开始执行代码. ROM 从 SD 卡读取 __bootcode.bin __, 它被载入到 C2 缓存中的内存, 并启动其余的 RAM, 随后 __start.elf__ 被载入.

__start.elf __是图形处理器的一个操作系统, 它会读取 __config.txt __, 你可以对它进行修改. 随后 __kernel.img __被载入内存中的 __0x8000__, 也就是 Linux 内核.

载入之后, __kernel.img __会启动 CPU, 并从内存中的 __0x8000 __开始运行.

如果我们愿意, 我们可以创建自己的 __kernel.img__, 把机器码硬编码进一个文件, 替换掉原来的镜像, 然后重启. 请记住, ARM 的字长是 32 位, 也就是从 bit 0 到 bit 31.

如前所述, 当 __kernel.img__ 被载入时, 第一个字节 (8 位) 会载入到地址 __0x8000__.

让我们打开一个十六进制编辑器, 写入以下内容:

__FE FF FF EA__

把文件保存为 __kernel.img__ 并重启.

"好吧, 什么都没发生, 太差劲了!"

实际上确实有事情发生了, 你写出了自己的第一个裸机 (bare-metal) 固件! 是时候开香槟庆祝了!

当 Pi 启动并运行到 __kernel.img __时, 下面的代码会载入以下内容:

__FE FF FF EA__

__@ 地址 0x8000, 0xfe 被载入.__

__@ 地址 0x8001, 0xff 被载入.__

__@ 地址 0x8002, 0xff 被载入.__

__@ 地址 0x8003, 0xea 被载入.__

"那到底究竟发生了什么?"

这组指令只是执行了一个无限循环.

请查阅数据手册 (datasheet):

<a href="https://www.raspberrypi.org/wp-content/uploads/2012/02/BCM2835-ARM-Peripherals.pdf" rel="nofollow noopener" target="_blank">https://www.raspberrypi.org/wp-content/uploads/2012/02/BCM2835-ARM-Peripherals.pdf</a>

上面的代码包含 3 个部分:

1)条件码 - 设置为总是执行

2)操作码 (Op Code) - 分支 (Branch)

3)偏移量 - 在当前位置上要移动多远

__条件码 - bit 31-28: 0xe 或 1110__

__操作码 - bit 27-24: 0xa 或 1010__

__偏移量 - bit 23-0 -2__

我知道这些内容可能有点难以消化, 但你花时间读一读上面链接的数据手册是至关重要的. 如果你真的有心弄懂上面的内容, 就不要偷工减料. 去读数据手册!

"我觉得很无聊! 这些破东西到底有什么要紧的?"

很高兴你问了! 当今地球上最危险的恶意软件就是 root-kit 这一类. 如果你对上面的内容没有基本的理解, 那么随着你理解的深入, 你连 root-kit 是什么都无法开始理解.

任何人都可以简单地用自己的修改版替换 __kernel.img__ 文件, 从而从启动开始就完全掌控整个过程.
